# 主动私聊工具 Plus (maibot_private_chat_tool_plus)

一个 MaiBot 插件：把「主动私聊」从只能发首条消息，升级为**多轮来回的传声筒**（"无限制"指对话轮次不受首条消息限制；使用仍受管理员配置的授权名单与频率限制约束）。全部交互基于自然语言，由 Planner 与 Replyer 驱动；不修改 Napcat 适配器本体，只通过其公开 API 与宿主能力协作。

- 插件 ID：`github.xiaocutedog.private-chat-tool-plus`
- 状态文件位置：`data/plugins/github.xiaocutedog.private-chat-tool-plus/relay_tasks.json`

## 功能

1. **多轮主动私聊**：Planner 可反复调用 `send_private_chat` 工具给同一个 QQ 用户发消息，没有"只能发首条"的限制。消息走宿主统一发送管线，正常入库并进入对方私聊流上下文，bot 与对方可以像正常私聊一样来回对话。
2. **自动人称**：A 让 bot 对 B 传话时，Planner 会按工具约定在消息里带上 A 的称呼（如「XX让我问你……」）；A 明确说「别说是我说的」时，则改为 bot 自己的转述口吻。
3. **发送成功反馈**：每次发送结果（成功或失败原因）都会回传给 Planner，由它自然地告知请求者；首次联系某用户且等待回复时，反馈中还会提示"若适配器开启私聊名单过滤需管理员放行，回复才能送达"。
4. **提问结果回传**：消息里包含需要对方回答的问题时，对方回复后插件会自动把回复转告请求者所在的聊天流。是否等待由工具参数 `ask_reply` 控制，**未指定时默认等待**（`relay.wait_reply_default`）。对方连发多条会自动合并转达（默认 15 秒静默期）。
5. **超时与异常提示**：超过等待时限对方仍未回复时，通知请求者；如果怀疑回复被适配器私聊名单过滤拦截，提示语中会附带排查建议。

## 安装与启用

1. 把本插件目录放进 MaiBot 的 `plugins/` 下（与其他插件同级）。
2. 启动/重启 MaiBot（或在 WebUI 插件管理中重载），确认日志中出现「私聊传声筒 Plus 已加载」。
3. 首次使用前必须配置授权：编辑插件目录下的 `config.toml`（首次加载时自动生成），把至少一个用户 QQ 加入白名单：

   ```toml
   [security]
   mode = "whitelist"
   users = ["你的QQ号"]
   ```

4. 配置支持热更新，保存 `config.toml` 即生效，无需重启。
5. 验证：在 bot 的私聊里说「帮我跟 <某好友> 说一句话」，观察是否返回转达反馈。

## 使用方式

对 bot 说自然语言即可，例如：

- 「帮我跟小明说，晚上七点老地方见」
- 「帮我问问 B 明天有没有空」→ B 回复「有空」→ bot 自动转告你
- 「跟 B 说取消明天的聚会，别说是我说的」
- 「再帮我问一句 B 带不带伞」（多轮继续）

未获授权的用户请求传话时，工具会拒绝并提示需要管理员调整配置。

管理命令：

- `/私聊任务`：查看进行中的传话任务。普通用户只能看到**自己所在聊天流**发起的任务；本地操作员（bot_console）可以看到全部任务。
- `/私聊任务 取消 <对方QQ号>`：取消任务。只能取消**当前聊天流**发起的对应任务。

## 工作原理

```
A（群聊/私聊）──自然语言──> Planner
                              │ 调用 send_private_chat 工具（先做授权与限流检查）
                              ▼
                 本插件：解析目标（QQ号/名字）→ 已有私聊流直接复用，否则 open_session 创建
                              │ ctx.send.text（宿主管线，正常入库）
                              ▼
                      Napcat 适配器 → QQ 私聊发送给 B
                              │
B 回复 ──> 适配器入站 ──> Hook: chat.receive.after_process
                              │ 合并缓冲（默认 15 秒静默期）
                              ▼
        ctx.maisaka.proactive.trigger 唤醒 A 所在流的 Planner 转告 A
        （触发失败时自动回退为纯文本发送）
```

- **目标解析**：知道 QQ 号直接用；只说了名字时，插件会在 QQ 好友列表、当前群成员、已有私聊流中按备注/群名片/昵称匹配——**完全一致优先于包含匹配**，命中多个同分候选时列出最多 5 个候选请用户确认。好友/群成员查询依赖 Napcat 适配器的公开 API；适配器不可用时仅剩已有私聊流可参与匹配。
- **回复转达任务**：默认等 30 分钟，对方每次回复都会滚动延长等待窗口（单个任务最长存活 240 分钟）；对同一目标再次传话会刷新等待计时。任务状态持久化在插件 data 目录（不含消息正文，见「安全与隐私」），重启后自动恢复（已过期的任务不会恢复）。
- **多请求者共享转告**：若 A 和 C 都在等待 B 的回复，B 回复后两人都会收到转告。发送频率限制（按目标全局计数）不受此影响。

## 与 Napcat 适配器私聊名单过滤的关系（重要）

适配器默认开启 `enable_chat_list_filter`（白名单模式且名单为空），**非白名单用户的私聊回复会在适配器侧被拦截**，这正是不加插件时「只能发首条」的根源。本插件的发送不受影响（出站不过滤），但发送路径**不会**建立任何放行窗口——要稳定收到对方的回复，需要：

1. 在适配器配置中把常用联系人加入 `private_list` 白名单（推荐，适合固定联系人）；
2. 或在适配器配置中关闭 `enable_chat_list_filter`（对所有私聊放行，最省心）；
3. 可选：开启本插件的 `security.enable_adapter_open_tool`（默认关闭）。开启后插件在加载时会尽力启用适配器的 `open_private_chat` 工具——该工具发送首条消息时会建立 15 分钟临时放行，之后由 Planner 自行决定首条消息是否走它。**注意这会改动适配器的组件状态**，且放行仅覆盖 15 分钟，长期使用仍建议方案 1/2。

另外，QQ 平台本身可能限制向非好友发送私信（取决于对方隐私设置），此时发送会失败并把原因反馈给请求者，与插件配置无关。

## 安全与隐私

- **授权名单**（`security` 配置段）：`mode` 可切换 `whitelist`（白名单，默认）/ `blacklist`（黑名单），两份名单为 `users`（用户 QQ）与 `groups`（群号）。
  - **白名单模式**（默认）：仅名单放行。私聊发起要求发起者在 `users` 中；群聊发起要求群在 `groups` 中（发起者本人在 `users` 中时，在任何群都可用）。两份名单都为空时任何人不可用，需管理员先添加。
  - **黑名单模式**：命中 `users` 的用户或 `groups` 中群内成员的请求被拒绝，其余放行。
  - **发起者身份未知时一律拒绝**：拿不到发起者 QQ 的请求（如本地控制台消息）不匹配名单、无法按用户限流也无法留日志追查，因此两种模式下都直接拒绝。正常 QQ 私聊/群聊不受影响。
- **频率限制**：默认同一用户每小时 20 条、同一目标全局每小时 20 条、全体每小时 100 条（均可配置，0 为不限制）。按目标的全局限额用于防止对同一个号码的骚扰。**发送尝试（含失败的）都计入额度**，避免重试刷屏。频率记录仅保存在内存中，重启后重新计数。
- **状态落盘**：`data/plugins/github.xiaocutedog.private-chat-tool-plus/relay_tasks.json` 只保存任务的标识与时间信息（双方 QQ、目标显示名、聊天流 ID、到期时间），**不保存任何消息正文**；未转达的回复缓冲仅存在于内存中，重启即丢弃。任务过期或取消后即从文件移除，没有进行中的任务时状态文件会被删除。

## 配置说明

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `relay.wait_reply_default` | `true` | 工具未显式指定 `ask_reply` 时是否默认等待回复 |
| `relay.reply_timeout_minutes` | `30` | 等待对方回复的超时（分钟） |
| `relay.max_task_lifetime_minutes` | `240` | 单个任务最长存活时间（分钟） |
| `relay.aggregate_seconds` | `15` | 对方连发多条消息的合并静默期（秒） |
| `relay.notify_on_timeout` | `true` | 超时后是否通知请求者 |
| `relay.hint_filter_issue` | `true` | 超时提示附带名单过滤排查建议 |
| `relay.notify_via_planner` | `true` | 用 Maisaka 主动回合转告（人格化表达）；关闭则发纯文本；触发失败时也会自动回退纯文本 |
| `send.platform` | `qq` | 目标平台标识 |
| `send.use_friend_list` | `true` | 按名字解析目标时查询好友列表 |
| `send.use_group_members` | `true` | 按名字解析目标时查询当前群成员 |
| `send.polish_content` | `false` | 发送前用 replyer 模型润色内容 |
| `security.mode` | `whitelist` | 授权模式：`whitelist` 白名单（默认）/ `blacklist` 黑名单 |
| `security.users` | `[]` | 用户 QQ 名单（白名单模式=允许使用；黑名单模式=拒绝使用） |
| `security.groups` | `[]` | 群号名单（白名单模式=允许使用；黑名单模式=拒绝使用，对群内所有人生效） |
| `security.max_sends_per_user_per_hour` | `20` | 同一用户每小时发送上限（0 不限） |
| `security.max_sends_per_target_per_hour` | `20` | 同一目标每小时全局被发送上限（0 不限） |
| `security.max_sends_total_per_hour` | `100` | 全体每小时发送上限（0 不限） |
| `security.enable_adapter_open_tool` | `false` | 加载时启用适配器 `open_private_chat` 工具（会改动其他插件组件状态，需显式开启） |

## 依赖

- MaiBot Host ≥ 1.2.0，SDK ≥ 2.5.0
- 可选配合：`maibot-team.napcat-adapter`。发送走宿主统一管线，`send.platform` 理论上可指向其他平台网关；但**按名字解析目标、查询登录账号（防误发给自己）等增强能力依赖 Napcat 适配器的公开 API**——适配器离线时这些能力降级，直接给 QQ 号仍可尝试发送（能否送达取决于平台网关是否在线）。
